# Mitwirken

Dieses Repository beschreibt ein Betriebsmodell, kein Produkt. Es lebt davon, dass Leute aus der Praxis widersprechen.

## Besonders willkommen

- **Was an der Rollentrennung gescheitert ist** — und welche abgeschwächte Form bei Ihnen gehalten hat
- **Erfahrungen mit Stundenbudgets**: welcher Aufwand tatsächlich angefallen ist, gemessen gegen die Zuweisung
- **Ergebnisse der Häufigkeitssortierung**: wie oft stand dieselbe Person in Ihrer Tabelle?
- **Eskalationen, die nicht stattgefunden haben** — und warum nicht. Das ist der aufschlussreichste Beitrag, den es gibt
- **Freigabetore, die umgangen wurden**, mit dem Grund
- **Weitere Eskalationsauslöser**, die sich als nötig erwiesen haben
- **Korrekturen an Rechtsbezügen und Fristen** — mit Fundstelle und Datum
- **Übersetzungen** einzelner Dokumente

Die vierte Zeile ist die wertvollste. Dieses Repository behauptet, dass Eskalationswege an vier Gründen scheitern; wer einen fünften kennt, sollte ihn melden.

## Weniger hilfreich

- **Gremien als Zuständige.** Gremien können beraten und vorbereiten. Verantworten kann nur eine Person, und danach wird in einer Prüfung gefragt
- **Ein Reifegrad für Governance.** Er würde die Zahl der gefüllten Felder messen, nicht die Tragfähigkeit des Modells
- **Musterformulierungen für Eskalationsschreiben.** Eine Eskalation braucht einen konkreten Entscheidungsvorschlag mit Alternativen und Risiken; ein Muster erzeugt eine Meldung
- **Weitere Rollen.** Drei sind schon an der Grenze dessen, was eine Organisation unter 100 Beschäftigten besetzen kann
- Reine Umformulierungen

Alle vier sind bewusste Entscheidungen. Wer sie für falsch hält, gern — aber mit Begründung im Issue.

## Was hier nicht wiederholt wird

Inventar, Einstufung, Prüfung, Dokumentation und Audit-Vorbereitung haben eigene Repositories. Dieses behandelt nur die Frage, wer was entscheidet und prüft. Das [Repository-Netz](./docs/repository-network.md) zeigt, wohin ein Beitrag gehört.

## Vorgehen

Kleine Korrekturen gern direkt als Pull Request. Bei größeren Änderungen vorher ein Issue.

`npm run validate` prüft, dass alle Pflichtpfade vorhanden und die JSON-Dateien lesbar sind. Die Prüfung läuft auch in CI.

## Rechtliches

Beiträge stehen unter der MIT-Lizenz dieses Repositories. Inhalte hier sind keine Rechtsberatung; wer eine Fundstelle ändert, gibt bitte die Quelle an.

**Keine Personendaten in Beispielen.** Dieses Repository verlangt an vielen Stellen Namen; in Beiträgen gehören sie erfunden. Eine Zuständigkeitstabelle mit echten Namen oder eine Überlastbeobachtung, die eine Person identifizierbar macht, gehört nicht in ein öffentliches Repository.

## Kodierung

Alle Dateien sind UTF-8. Das klingt selbstverständlich, war es in diesem Repository aber eine Weile nicht — deutsche Umlaute erschienen auf GitHub als Ersatzzeichen. Wer unter Windows arbeitet, prüft das vor dem Commit.
